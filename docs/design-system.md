# 界面设计规范

CloudLink 的界面采用「安静钢面」：中性画布、清晰列表、细分隔线和真实品牌标识。颜色主要表达状态，日常操作不需要理解内部编译、分发或运行环境机制。

本文记录当前组件的使用约定。颜色数值、尺寸和状态实现以 [全局样式](../src/index.css) 与 [UI 组件](../src/components/ui/) 为准，不在文档中再维护一套完整令牌值。影响这些约定的改动，应同时更新实现、测试和本文。

## 设计原则

- **正常状态保持安静。** 连接、分发正常时不堆叠解释；需要处理的问题回到对应资源或设置行。
- **主次操作清楚。** 一项任务突出一个主操作，次要操作使用中性按钮或文字入口。
- **状态不只靠颜色。** 状态点配合文字、图标或可访问名称；不能让读屏和键盘用户依赖颜色猜测。
- **复用现有模式。** 添加、编辑、设置和详情使用同一套组件与表面，不为单个功能另建视觉语言。
- **信息与控件有区别。** 地址、命令、名称和错误信息需要能够复制；可点击项需要有明确反馈。

## 颜色与表面

颜色在 `src/index.css` 的 `:root` 与 `.dark` 中成对定义，经 `@theme inline` 映射到组件使用的语义名称。

| 令牌 | 用途 |
| --- | --- |
| `background`、`foreground` | 窗口画布与主要文字 |
| `card`、`card-2` | 列表／对话框及次级内容表面 |
| `pill`、`pill-hover`、`seg-track` | 中性控件、悬停状态和分段切换轨道 |
| `line`、`line-2` | 容器边界与卡内分隔线 |
| `fg-2`、`muted-foreground`、`ctl-fg` | 次级说明、辅助文字与控件文字 |
| `primary`、`ink` | 主操作；深色主题使用对应的反色值 |
| `signal`、`signal-soft`、`ring` | 选择、文字链接与键盘焦点等强调状态 |
| `success`、`warning`、`destructive` | 正常、需处理和失败／危险状态 |

新增界面优先使用这些语义令牌，不在业务组件里随意加入新的十六进制或 OKLCH 色值。品牌 Logo 的官方颜色与应用状态色是不同用途。

页面和列表通常是平面表面，靠背景明度与分隔线建立层次；阴影主要属于菜单、对话框、提示等浮层，不给每一行增加阴影。

## 字体、密度与形状

- UI 使用 Segoe UI 与中文系统字体回退，不另外打包展示字体。
- 机器可读信息使用 `font-mono`，对应 Cascadia Mono、Consolas 等回退；普通说明不使用等宽字体。
- 资源、设置和导航常用紧凑正文；辅助信息降低层级，详情标题使用较大的标题样式。具体尺寸沿用对应组件，不为每个页面重新建立字号表。
- 时间、端口和计数使用等宽数字对齐。
- 圆角使用 `control`、`button`、`tile`、`popover`、`list`、`dialog` 等已有角色；不要用一个任意圆角覆盖所有组件。

[Button](../src/components/ui/button.tsx) 已提供默认、紧凑、图标、标题及工具栏变体。优先选择合适的 `variant`／`size`，而不是在调用处复制整套按钮样式。

## 窗口与页面布局

[窗口配置](../src-tauri/tauri.conf.json) 的默认尺寸为 1000×680，最小为 760×520，保留原生系统装饰。

- 原生标题栏负责窗口标题与窗口操作；WebView 导航不再复制一套窗口按钮。
- [应用导航](../src/components/app/AppHeader.tsx) 支持顶栏和侧栏，导航项目及其语义保持一致。
- 资源、Agent、设置及详情主要使用居中的单列内容；常用容器上限是 `max-w-190`，动态视图按自身内容使用较窄容器。
- 详情替换主内容，不靠常驻左右分栏同时塞入列表与全部详情。
- 小窗口下优先保证主要操作与滚动区域可用，不能只对默认窗口尺寸排版。

源文件：[App](../src/App.tsx)、[资源列表](../src/features/servers/ResourceList.tsx)、[详情布局](../src/features/servers/DetailParts.tsx)。

## 主要组件模式

### 资源行与 Agent 选择

[资源行](../src/features/servers/ResourceRow.tsx) 采用单名称体验，以显示名称、连接状态和档位为主，右侧提供 Agent 选择及按需的修复入口（底层 SSH 别名退居详情「连接信息」分组，不与显示名称并排挂出）。

- 行内控件独立处理操作，不应意外触发整行导航。
- 连接问题与当前档位是不同信息，不混成一串同样外观的徽章。模式仅「确认变更／自动运维」；任意资源从确认变更切到自动运维均需中性轻确认（不加琥珀色文字或托盘圆点提醒），取消保持原状态；托盘提供「全部改为确认变更」。
- Agent 选择表示资源是否选给该目标，不等于真实账号权限，也不能代替送达结果。点谁只改谁，不自动扩选；共用目录只提供共同选择的交集，不能提供时在原有问题行说明。
- 成功、部分送达、冲突和失败需要反映实际返回状态，不能只凭请求完成就展示“已同步”。

### 设置式列表

复用 [SettingsList](../src/components/app/SettingsList.tsx) 的 `ListGroup`、`PrefRow` 等组合：左侧名称与说明，右侧值或操作；长内容使用既有的纵向布局。问题行保留在对应分组，使用 `bg-warning/5` 与既有琥珀文字令牌，保证文字对比度；少用的内容可以折叠，不另造一套设置容器。

### 添加与编辑

基础浮层来自 [Dialog](../src/components/ui/dialog.tsx)。资料与连接编辑复用 [DraftDialog](../src/features/servers/DraftDialog.tsx)：

- 固定标题和底栏，只有正文滚动。
- 编辑变体限制最大宽高，并为小窗口保留外边距。
- 草稿先留在表单内，保存成功后再更新背景详情。
- 放弃未保存内容的确认在同一底栏完成，不叠加第二个模态框。
- 确认或保存过程中禁用不合适的操作；关闭后恢复入口焦点。

表单标签、错误、提示和禁用原因需要完整，不能只依靠占位符表达字段含义。错误优先出现在相关字段、行或流程步骤中。

Skill 预览使用居中宽 `Dialog` + 左侧文件树（窄窗自动退化为顶栏文件下拉），顶部单行操作栏、YAML Frontmatter 默认折叠、底部仅保留编译目录路径与安静的字数／行数参考；真实安全告警按当前查看文件归属展示，并直接提供直达对应编辑入口的修复按钮。

### 品牌与图标

通用图标使用 Lucide。Agent 与云平台的品牌显示只通过 [AgentMark](../src/components/app/AgentMark.tsx) 和 [ProviderMark](../src/components/app/ProviderMark.tsx)，不以通用图标或文字缩写冒充品牌。明暗主题下沿用封装的单色 Logo 适配。

审批卡与操作记录通过 [InvocationAvatar](../src/components/app/InvocationAvatar.tsx) 显示实际调用品牌；未知使用 BotIcon 与“未知来源”，自报品牌明确标注“自报”，不能根据分发目录猜测。调用来源与检查通道分别显示，允许一次、执行中、成功与未知结果不能混为一个状态。

## 动效与可访问性

- 全局动画配置见 [入口文件](../src/main.tsx)，使用 `MotionConfig` 并尊重 `reducedMotion="user"`。
- 组件自带 CSS 动效的减弱规则位于 [全局样式](../src/index.css)；新增位移、缩放或展开效果时也必须考虑这一设置。
- 原地更新档位、选择或状态，不应重播整页入场或重置滚动位置。
- 通过键盘可以到达主要操作，焦点可见；导航、选择和禁用状态使用对应的 ARIA 语义。
- 模态框限制焦点并恢复入口，关闭与返回动作不能吞掉未保存的草稿。
- 可访问性以 WCAG 2.2 AA 为目标；不能仅凭颜色值或组件来源就宣称已通过验收。

## 文案与状态反馈

所有界面文字集中在 [copy.ts](../src/lib/copy.ts)。按钮写具体动作，说明写用户能得到的结果，避免把实现细节当成帮助文案。

加载、成功、失败、未验证、未送达是不同状态。数据加载失败不能伪装成空列表；禁止的操作要说明原因，能够修复的问题尽量提供就近入口。

## 修改后的检查

涉及界面的修改，除 [贡献指南](../CONTRIBUTING.md) 中的工程检查外，还应验证：

- 浅色／深色与顶栏／侧栏组合。
- 默认与最小窗口尺寸下的长名称、错误文字、滚动和底栏。
- 键盘导航、焦点恢复、Esc、输入法组词及草稿防丢。
- 减少动态效果和缩放后的可用性。
- 涉及标题栏、托盘或原生窗口行为时，在真实桌面验证；浏览器 Mock 截图不能替代。

不要为了文档整齐而改动现有界面，也不要把未实现的设计设想写成当前组件能力。
